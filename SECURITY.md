# Security Policy

## Supported Scope

This repository is a **research / simulation project** intended for analytical, educational, and experimental use.

The following are **in scope** for security reporting:

- Accidental exposure of secrets, credentials, or tokens
- Vulnerabilities that could cause unintended data disclosure
- Critical flaws that enable remote code execution in documented usage paths
- Supply-chain risks introduced by declared dependencies

The following are **out of scope**:

- Hypothetical or purely theoretical attacks with no practical exploit path
- Issues requiring undocumented, non-standard, or malicious usage
- Denial-of-service reports based on unrealistic load assumptions
- Findings from automated scanners without manual validation

---

## Reporting a Vulnerability

If you believe you have discovered a **legitimate security vulnerability**, please report it responsibly.

### Preferred method
- Open a **GitHub Security Advisory** using the repository’s Security tab  
  (private disclosure is preferred)

### Alternative
- If private reporting is unavailable, you may open an issue with:
  - Clear reproduction steps
  - A concise threat model
  - Proof-of-concept (if applicable)

Do **not** publicly disclose vulnerabilities before coordination.

---

## Disclosure Policy

- Valid reports will be acknowledged within a reasonable timeframe
- Fixes may be released silently or with a security note, depending on severity
- This project does **not** currently run a bug bounty program

---

## Legal & Ethical Notice

By submitting a report, you confirm that:
- You did not exploit the vulnerability beyond minimal proof
- You acted in good faith
- You complied with applicable laws and ethical standards

Thank you for helping improve the safety and integrity of this project.
